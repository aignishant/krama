# Daily track completion

Reading and author-provided demos do not complete learner objectives. Check these only against
your own work; the tracks may be completed in separate sittings.

## Read and explain

- [ ] DSA: read [the scan lesson](dsa_count-target-values/CONCEPTS.md), trace its state, and explain initialization, maintenance, and termination.
- [ ] DSA online route: read [reusing counts](dsa_count-target-values/FREQUENCY_COUNTS.md) and explain frequencies, strict boundaries, duplicates, and the saved work; optional for the local route.
- [ ] SD: read [the scope lesson](sd_functional-scope/CONCEPTS.md) and distinguish a user outcome from an implementation choice.
- [ ] Python: read [the identity lesson](lang_identity-and-equality/CONCEPTS.md) and distinguish mutation from rebinding.
- [ ] Answer the selected track's readiness points before opening its assignment.

Later recall needs no new exercise: [DSA](../../docs/DSA_RECALL.md),
[Python](../../docs/LANG_RECALL.md), [system design](../../docs/SD_RECALL.md).

## Practice and verify

- [ ] DSA: choose one main route, attempt independently, test distinguishing inputs, and justify correctness and time/space.
- [ ] DSA: record an observed failure or counterexample and its repair; local tests do not count as online acceptance.
- [ ] SD: write three user actions, two exclusions, one measurable criterion, a request/failure trace, and an alternative.
- [ ] Python: predict before running, implement the list experiment, and record a failing assumption plus a meaningful regression assertion.
- [ ] Save actual evidence and any hints in the appropriate subject files.

## Record completion

- [ ] DSA core and its acceptance criteria complete.
- [ ] SD deliverable and critique complete.
- [ ] Python experiment and explanation complete.
- [ ] Append separate track results; append whole-day progress only when all three pass.
